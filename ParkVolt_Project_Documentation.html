1. Executive Overview & System Architecture

ParkVolt is a smart mobility platform designed to solve urban parking congestion and streamline electric vehicle (EV) charging reservations across major metropolitan cities. The platform provides real-time telemetry representation, dynamic slot reservations, cryptographic authentication, and simulated IoT sensor monitoring without relying on external server latency or database downtime.

1.1 Three-Tier Client Architecture

The system is designed with a strict separation of concerns into three foundational layers:

Tier 1: Presentation & WebGL Canvas Layer
Renders 10 responsive user pages and the interactive 3D digital-twin city island via WebGL on the client GPU. Manages lighting adaptation for Day/Night modes and handles user pointer raycasting events.
Tier 2: Business Logic & State Management Layer
Built using React Context API (BookingContext, AuthContext, ThemeContext). Executes the real-time 4-second sensor fluctuation engine, client-side SHA-256 Web Crypto hashing, and mathematical interval collision prevention algorithms.
Tier 3: Persistence & Mock Data Layer
Pre-seeds authentic municipal parking locations and high-speed DC charging stations from structured JSON files, while maintaining persistent user sessions, booking passes, and digital wallet balances inside the browser's localStorage.

2. End-to-End System Workflow (Step-by-Step)

The complete user lifecycle follows an automated 7-step sequence from discovery to active gate verification and refund execution:

Step 1: System Theme & 3D Lighting Adaptation
When a user opens the app, ThemeContext checks prefers-color-scheme or saved user preferences. In Light Mode, the 3D scene renders an ambient daylight sky; in Dark Mode, it dynamically illuminates building windows, streetlamps, and car headlights while switching page CSS variables.
Step 2: Exploration & Search Query Propagation
Users explore the 3D island or submit search queries from the landing hero. Entering a query redirects to /find-parking?q=City, filtering initial seed data by facility name, city, and parking amenities (Covered, EV, CCTV).
Step 3: EV Charger Filter Matrix
Navigating to /find-ev enables multi-variable filtering across Indian EV standards: Type 2, CCS2, CHAdeMO, Bharat AC001, and Bharat DC001, sorting chargers by power output (>50 kW fast superchargers) and availability.
Step 4: Interactive 3D Slot Selection & Pricing Formula
On /parking/:id, the 3D slot picker allows users to click open bays directly in WebGL. Users select a reservation start time and duration (30 min to 24 hrs). The system computes total cost dynamically: Subtotal = Rate × Hours, adding an itemized 18% GST tax breakdown.
Step 5: Pre-Checkout Double-Booking Collision Check
Before finalizing checkout, the system invokes checkDoubleBooking(). It performs interval collision checks against all active reservations. If an overlap exists, it halts checkout and notifies the user with a collision alert toast.
Step 6: Payment Execution & Wallet Ledgering
Users select UPI (VPA format check), Credit/Debit Card (Luhn format check), or 1-Click ParkVolt Prepaid Wallet. Transactions are logged into an immutable digital ledger in localStorage.
Step 7: Dynamic SVG QR Ticket, Extension & Cancellation
The user is redirected to /ticket/:id where an encrypted SVG QR code is generated via qrcode.react alongside a real-time countdown. Users can extend by +30 minutes or cancel to receive an instant 100% wallet refund.

4. Algorithmic Deep-Dive & Viva Defense Guide

4.1 Double-Booking Collision Prevention Formula

In BookingContext.jsx, the collision algorithm prevents two users from reserving the same bay for overlapping durations. Mathematically, two time intervals [S1, E1] and [S2, E2] overlap if and only if:

Overlap Condition: (ExistingStart < RequestedEnd) AND (ExistingEnd > RequestedStart)
If this condition returns true for any non-cancelled booking on the requested slot, reservation is rejected. 
// Implemented in BookingContext.jsx
const checkDoubleBooking = (slotCode, startTime, endTime) => {
  const reqStart = new Date(startTime).getTime();
  const reqEnd = new Date(endTime).getTime();

  return bookings.some((b) => {
    if (b.slotCode !== slotCode || b.status === "cancelled") return false;
    const bStart = new Date(b.startTime).getTime();
    const bEnd = new Date(b.endTime).getTime();
    return bStart < reqEnd && bEnd > reqStart; // Collision detected
  });
};

4.2 Top 5 Viva Questions & Model Answers

Q1: How is high 3D rendering performance achieved without lag or stutter?
Ans: We capped the WebGL pixel ratio to dpr={[1, 2]} to prevent GPU saturation on high-DPI displays. All 3D objects use low-polygon geometric primitives (boxes, cylinders, cones), and animations are updated inside the Three.js useFrame() hook using delta time instead of triggering React state re-renders.
Q2: Why use the W3C Web Cryptography API instead of plain text storage?
Ans: Storing passwords as plain text in localStorage is vulnerable to Cross-Site Scripting (XSS). By hashing passwords using crypto.subtle.digest("SHA-256", ...), user passwords are converted into a one-way hexadecimal hash before being stored or evaluated.
Q3: How does the system simulate real-time IoT parking sensors?
Ans: A lightweight background interval runs every 4 seconds in BookingContext. It randomly fluctuates bay occupancy by ±1 to simulate live ultrasonic sensors and ANPR camera feeds, while transparently displaying a "Simulated data" badge across the interface.
Q4: How does the application prevent blank white screens if a component fails?
Ans: The application incorporates a top-level React ErrorBoundary in App.jsx that implements getDerivedStateFromError() and componentDidCatch(). If any child component encounters an exception, it displays a friendly error interface with a one-click reload button rather than unmounting the entire DOM.
Q5: How does the dynamic QR ticket work?
Ans: We use qrcode.react to generate a vector SVG QR code. It encodes a structured JSON payload containing the Booking ID, Slot Code, User ID, and cryptographic timestamp, allowing smart barrier scanners to parse and validate entrance permits instantly.
